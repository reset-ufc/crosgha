# Releasing

Versioning is driven entirely by [Conventional Commits](https://www.conventionalcommits.org/)
on `master`, via [release-please](https://github.com/googleapis/release-please).
Never bump the version or edit CHANGELOG.md by hand.

## Flow (two workflows)

1. Merge Conventional Commits to `master` (`commit-msg` hook enforces it).
2. `release-please.yml` opens/updates a release PR (SemVer bump,
   `bump-minor-pre-major: true` — pre-1.0, breaking changes bump minor) and
   the CHANGELOG.md entry. Merging it makes release-please tag `v<version>`
   and create a **draft** GitHub Release (`"draft": true` in the config).
3. Its `dispatch-dist-release` job runs `gh workflow run release.yml --ref
   <tag> -f tag=<tag>` (`actions: write` scoped to just that job; `--ref <tag>`
   so the build uses the tagged commit even if `master` moved on). A
   tag/release made with the default `GITHUB_TOKEN` does not trigger other
   `on: push: tags` workflows (GitHub's anti-recursion rule; a PAT was ruled
   out) — but `workflow_dispatch` is the documented exception, an explicit
   API call rather than an implicit event.
4. `release.yml` (cargo-dist, `dispatch-releases = true`) builds the 3
   targets and uploads the archives + `.sha256` to that same draft release,
   then undrafts it (`create-release = false`: cargo-dist never calls
   "create a release" itself, so there's no duplicate).

## One-time setup on GitHub (not done by this repo)

- Create the GitHub repo, push `master`, replace the `repository` placeholder
  in `Cargo.toml`.
- Settings > Actions > General: "You may also need to set 'Allow GitHub
  Actions to create and approve pull requests'" (release-please-action's
  README) — required for its release PR with the default `GITHUB_TOKEN`.

## cargo-dist's release.yml

`release.yml` is generated by `dist generate` and then hardened by hand (SHA pins, permissions, timeouts).
`dist-workspace.toml` sets `allow-dirty = ["ci"]` so `dist plan`/`dist init` do not report that hardening as drift.
Its `${{ matrix.* }}` interpolations come from `dist plan` output for this repo's own config, not from attacker input.
Workflow hygiene is checked by our-tool itself once it has rules; no third-party workflow linter is used.
