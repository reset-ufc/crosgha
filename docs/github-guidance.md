# What GitHub's documentation asks of a workflow

This page maps the normative statements in GitHub's own Actions documentation to the rules crosgha has for them. It reflects [github/docs](https://github.com/github/docs) at commit [`44f009d`](https://github.com/github/docs/tree/44f009da482ef1470b37ffea456821014d892a1f), read on 24 November 2026. Each quote is linked to the line it comes from at that commit, so a later edit upstream shows up as a missing quote rather than as a silent drift.

Of the 94 statements below, 24 map to a rule, 15 are covered only partly, and 55 have no rule. "Partly" means the rule checks part of what GitHub asks, or checks it more strictly. "Not checked" means no rule in the [catalog](rules.md) decides it from the files crosgha reads. A rule link opens the rule's examples, where its summary and its non-compliant and compliant YAML sit; the full catalog is in [Rules](rules.md).

crosgha reports a finding only for the rules marked below and only at the persona that includes them: `regular` by default, `pedantic` for hardening, `auditor` for heuristics that may be false positives ([personas](configuration.md#personas)). A statement with no rule is still worth reading: some of it is operational advice no static check can settle.

## Permissions and `GITHUB_TOKEN`

GitHub states the default the token gets and the key that narrows it. Most of this section is about what the token may do, not about what a job does with it.

GitHub's pages: [actions/reference/workflows-and-actions/workflow-syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), [actions/reference/security/secure-use](https://docs.github.com/en/actions/reference/security/secure-use).

| What GitHub asks | Quote | crosgha |
|---|---|---|
| Grant the `GITHUB_TOKEN` only the access a job needs, through `permissions`. | "You can use `permissions` to modify the default permissions granted to the `GITHUB_TOKEN`, adding or removing access as required, so that you only allow the minimum required access." ([section-assigning-permissions-to-jobs.md:1](https://github.com/github/docs/blob/44f009da482ef1470b37ffea456821014d892a1f/data/reusables/actions/jobs/section-assigning-permissions-to-jobs.md#L1)) | [`missing-permissions-block`](rule-examples.md#missing-permissions-block) |
| Treat a `pull_request_target` run as holding a write `GITHUB_TOKEN`, even from a public fork. | "When a workflow is triggered by the `pull_request_target` event, the `GITHUB_TOKEN` is granted read/write repository permission, even when it is triggered from a public fork." ([section-assigning-permissions-to-jobs.md:7](https://github.com/github/docs/blob/44f009da482ef1470b37ffea456821014d892a1f/data/reusables/actions/jobs/section-assigning-permissions-to-jobs.md#L7)) | [`dangerous-trigger`](rule-examples.md#dangerous-trigger) |

## Script injection

Event data that reaches a shell or an API call. GitHub's own rule is to route it through `env`.

GitHub's pages: [actions/reference/security/secure-use](https://docs.github.com/en/actions/reference/security/secure-use), [actions/concepts/security/script-injections](https://docs.github.com/en/actions/concepts/security/script-injections).

| What GitHub asks | Quote | crosgha |
|---|---|---|
| Pass untrusted input to a script through an intermediate environment variable. | "For inline scripts, the preferred approach to handling untrusted input is to set the value of the expression to an intermediate environment variable." | Consider that any script may execute attacker-supplied input. | "you should always consider whether your code might execute untrusted input from attackers" ([script-injections.md:15](https://github.com/github/docs/blob/44f009da482ef1470b37ffea456821014d892a1f/content/actions/concepts/security/script-injections.md#L15)) | [`script-injection`](rule-examples.md#script-injection) |
| Treat contexts ending in `body`, `ref`, `title`, `head_ref`, and the like as untrusted. | "These contexts typically end with `body`, `default_branch`, `email`, `head_ref`, `label`, `message`, `name`, `page_name`,`ref`, and `title`."
